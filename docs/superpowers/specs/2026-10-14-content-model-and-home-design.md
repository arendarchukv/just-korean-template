# Content model, Pages CMS and home page — design

Date: 2026-10-14. Status: approved in conversation, awaiting review of this written spec.

## Why

The owner (JiEun, teacher behind the Just Korean YouTube channel) sent the features she wants:
class booking (TidyCal), flashcards, downloadable materials, pronunciation practice, dictionary,
email contact, videos with downloadable transcripts, quizzes whose results reach her, and Korean
news reading. The current site is an unstable AI-generated React SPA; in it the dictionary and
pronunciation are only links (krdict, 누리-세종학당) and flashcards are generated by Gemini.

The site is a library built on her YouTube channel: videos stay on YouTube, the site adds
structure, grammar lookup, materials, practice and a path to her classes. Her channel playlists
already map onto site sections (Crash Course 10, Grammar 54, Vocabulary 28, Pronunciation 11,
Speaking like a Korean 6, Shadowing 6, Podcast 21, Listening 20). Most grammar videos compare two
patterns ("아/어 있다 vs 고 있다"), so a grammar pattern is its own entity linked from videos.

She edits content herself in Pages CMS. **Editing must be comfortable**: short forms, a hint
under every field, search in pickers, no way to save content that breaks the site.

Earlier wireframes (claude.ai artifact "Just Korean — лого і сайт": home, videos, video page,
materials, practice, news) give structure; the existing design system ("Paper & cut-outs",
`/styleguide`) gives the look.

## Decisions

- **Flashcards:** ready-made decks written by her (thematic, or for a lesson or podcast episode).
  No AI.
- **Files:** every downloadable or embedded file (PDF, audio, transcripts, her photo) lives in
  **Cloudflare R2**; she uploads in the Cloudflare dashboard and pastes the URL into the CMS.
  The site stores only URLs. Pages CMS uploads only into Git, so it is not used for files.
- **Language:** only the interface is translated (EN default, KO under `/ko/`). Content exists
  once, in English with Korean examples; Korean pages show the same content with Korean UI.
  All content is read through one module (`src/content/queries.ts`), so optional per-entry
  translations can be added later in one place.
- **The hub is a lesson, not a video.** A lesson may have a YouTube video or not.
- **Not modelled now:** blog (not requested; notices cover school news), dictionary (a search box
  that opens krdict), pronunciation (a lesson series plus a link to 누리-세종학당), news reading
  (later, via RSS).
- **CMS labels:** English (changeable later in `.pages.yml` only).

## Content model

Content lives in `src/content/<collection>/`, one file per entry, the filename is the entry id
(slug). Long text uses Markdown with frontmatter; data-only entries use YAML. References store
the target entry id.

A shared **download** shape (Pages CMS component, zod schema):
`label` (string, required), `kind` (select: `pdf` | `audio` | `transcript`), `url` (https URL,
required). Hint: "Upload the file to R2 in the Cloudflare dashboard, then paste its public link."

### lessons (`.md`)

| field | type | notes |
|---|---|---|
| title | string, required | her wording, as on YouTube |
| youtube | string, optional | full YouTube link or 11-char ID; schema normalises to the ID |
| series | reference → series, optional | |
| episode | number, optional | position in an ordered series |
| date | date, required | sorts "new lessons" |
| level | select: beginner / intermediate / advanced | |
| grammar | reference → grammar, multiple, optional | patterns the lesson covers |
| summary | text, optional | one or two sentences for cards and meta description |
| downloads | list of download, optional | files for this lesson |
| body | Markdown | explanation or transcript |

### series (`.yml`)

`title`, `description` (text), `kind` (select: `course` = ordered with progress, `library`,
`podcast`), `youtubePlaylist` (URL, optional), `order` (number, display order on the site).

### grammar (`.md`)

`pattern` (string, e.g. `-아/어 봤자`), `meaning` (one line, English), `level`, `formation`
(text), `examples` (list: `ko`, `en`), `compare` (reference → grammar, multiple), body
(Markdown, optional). Lessons about a pattern are found by the site, not entered twice.

### materials (`.yml`)

`title`, `category` (select: `class-helper` | `podcast` | `extra-notes`), `tags` (list of
string), `date`, `files` (list of download, at least one), `lesson` (reference, optional).
The Materials page (later cycle) lists these together with lesson downloads.

### decks (`.yml`)

`title`, `level`, `description` (optional), `lesson` (reference, optional), `cards` (list:
`front` Korean, `back` meaning, `example` optional).

### quizzes (`.yml`)

`title`, `level`, `lesson` (reference, optional), `questions` (Pages CMS block list,
`blockKey: type`): `choice` {`prompt`, `options` list {`text`, `correct` boolean},
`explanation`} and `fill` {`sentence` with `___`, `answer`, `alternatives` list,
`explanation`}. Results go to her through a Tally form (later cycle).

### notices (`.yml`)

`title`, `text` (text), `from` (date), `to` (date), `tone` (select: `important` | `info`),
`link` (URL or site path, optional).

### settings (singleton files)

- `home.yml`: `greeting` ("Hi, I'm JiEun"), `intro` (text, two sentences), `photo` (R2 URL,
  optional), `photoAlt`, `credentials` (list of string), `newLessonsCount` (number, default 3).
- `classes.yml`: `formats` (list: `name`, `forWhom`, `how`), `faq` (list: `question`,
  `answer`). The home page and the Classes page read the same list.
- `site.yml`: `tidycal` (URL), `contactForm` (Tally URL), `quizResultsForm` (Tally URL),
  `filesBaseUrl` (R2 public base URL), `social` (`youtube`, `instagram`, `kofi`). Replaces
  `SOCIAL_LINKS` in `src/config.ts`.

### Rules she follows (also written as CMS hints)

"A file for a lesson goes into that lesson. A file on its own goes into Materials. Decks and
quizzes have their own sections and say which lesson they belong to."

## Pages CMS configuration

`.pages.yml` at the repo root: one `content` entry per collection (`type: collection`) and per
settings file (`type: file`); shared `components` for `download` and `level`; `reference`
fields with `search` on title/pattern; `view` with list columns, search and default sort (date
desc for lessons, materials, notices; `order` for series). Every field has a `description`
hint. No `media` block (files are R2 links).

The exact stored value of `reference` (`value` template) is verified during implementation; the
schema accepts the id, and strips a path or extension if Pages CMS stores one.

## Validation

- zod schemas in `src/content.config.ts` mirror the model: required fields, `https://` URLs,
  YouTube link → ID, `to` not before `from`, `episode` only with a series. A broken entry fails
  the build with the file name and field.
- Unit test: every collection and field in `.pages.yml` exists in the schemas and vice versa
  (form and site never drift).
- `npm run check:links`: HEAD-requests every download/photo URL and reports dead ones; skips the
  `.example` placeholder domain. Run before deploy, not in every build.

## Home page

Order, top to bottom:

1. **Notice strip** — full width, like a strip of paper tape: date label, one line, link,
   dismiss button. Shows active notices (important first, at most 2). Rendered at build;
   a small inline script hides notices outside `from`–`to`, so an expired notice disappears
   without a rebuild. Dismissal is remembered per notice in `localStorage` (try/catch).
2. **About her** — asymmetric: large "그냥 한국어" in a Korean serif (명조), greeting, two
   sentences, credentials as a quiet list on 원고지 grid paper (not stat badges); her photo
   clipped by an organic shape from the shape system (placeholder paper shape until she sends a
   photo). Actions: "Book a class" (primary, TidyCal) and "Watch lessons" (secondary).
3. **Classes** — a ruled table like a printed timetable: format, for whom, how it works, arrow
   to the Classes page; booking button below.
4. **What's on the site** — a 목차 (table of contents): numbered 01–05, section name in Korean
   and English, one line, arrow: Lessons & grammar · Materials · Flashcards & quizzes ·
   Pronunciation & dictionary · Korean news reading. UI copy in the i18n dictionary; sections
   not built yet link to their placeholder pages.
5. **New lessons** — the latest `newLessonsCount` lessons with a YouTube video: thumbnail,
   series label, date. Until the lesson page exists (next cycle) cards link to the lesson's
   future URL `/lessons/<id>/`, served by a minimal placeholder route.

Look and feel (no "AI template"): each block has its own form, not the same card; radii by role
(buttons 10px, thumbnails 12px, photo in a shape, lists and tables without boxes); blue only for
actions, teal only for learning marks; cut-paper shapes only in the About block; lots of white
space. Typography gets a second voice: a Korean serif for a few display lines, loaded only for
the glyphs used; Outfit and Pretendard stay for text and UI.

Header navigation stays as it is in this cycle; it changes when the sections exist.

## Images and fonts

- YouTube thumbnails (`https://i.ytimg.com/vi/<id>/hqdefault.jpg`) are fetched and optimised at
  build with `astro:assets` (remote domain allowed), served as local WebP with width/height.
  No request to Google from the visitor.
- Her photo: remote R2 URL, optimised at build the same way (R2 domain added once known).
- Serif display font: self-hosted, subset to the glyphs of the display lines.

## Demo content

Real, public data from the channel: 4–5 lessons (Crash Course and grammar comparisons) with
real titles and video IDs, 3–4 grammar entries with `compare`, series for the playlists used,
one active notice, `home.yml` (bio drafted from known facts: MA in Korean Language Education,
certified teacher, taught in Hong Kong, the Netherlands and Spain; marked for her review),
`classes.yml` (1:1, small group, group, from the current site), `site.yml` with placeholders.
Download URLs use the placeholder domain `files.just-korean.example`.

## Testing

Test first, as in earlier work:

- unit: YouTube link parsing, active-notice selection by date, lesson ordering and "new lessons"
  selection, `.pages.yml` ↔ schema match;
- `check:dist`: home has the five blocks in order, notice markup carries dates, thumbnails are
  local files, home links stay in the locale;
- axe a11y on home in both themes (existing suite; add the lesson placeholder route);
- performance budget on home with the serif font and thumbnails (LCP < 2 s, CLS < 0.1; font
  file limit revisited with a measured number).

## Out of scope (later cycles, each with its own spec)

1. Lesson page and series library. 2. Grammar reference. 3. Materials page. 4. Flashcards.
5. Quizzes with Tally results. 6. Dictionary search and pronunciation. 7. Korean news reading
(RSS). Also: daily rebuild on the host, an R2 upload page, content translations.

## Open, needs the owner

Her photo; bio wording; TidyCal and Tally URLs; R2 public domain; social links.
